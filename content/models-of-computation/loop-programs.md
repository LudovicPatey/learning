Register machines use jumps. Modern programming languages instead use **structured** control flow: sequences, conditionals and loops. We study two minimal structured languages, introduced by Meyer and Ritchie (1967): **LOOP**, whose only loop is a `for` loop executed a number of times fixed on entry, and **WHILE**, which adds a `while` loop. The distinction between the two loops corresponds exactly to the distinction between primitive recursion and minimization.

This lesson defines both languages and studies LOOP; the next lesson treats WHILE. The characterization of LOOP is proved by **compilation** in each direction. From functions to programs, each scheme of definition is implemented by a small program, and the programs of the subfunctions are combined with fresh variables so that they do not interfere. From programs to functions, the whole state of the variables is coded by one integer with the sequence coding of the lesson :ref{to="models-of-computation/coding-sequences"}, so that the effect of a loop becomes an iteration of a single function, that is, a primitive recursion. The same method gives the characterization of WHILE in the lesson :ref{to="models-of-computation/while-programs"}, where a loop becomes a search for the number of iterations, and, applied to Turing machines, Kleene's normal form theorem in the lesson :ref{to="models-of-computation/equivalence-of-models"}.

## Syntax and semantics

Programs manipulate **variables** $X_0, X_1, X_2, \dots$, each holding a natural number.

:::definition{#def-loop-while-syntax}
The **WHILE programs** are generated by the grammar
$$
\begin{aligned}
P \ ::=\ & X_i \mathbin{:=} 0 \ \mid\ X_i \mathbin{:=} X_i + 1 \ \mid\ X_i \mathbin{:=} X_j \ \mid\ P ; P \\
\mid\ & \mathtt{LOOP}\ X_i\ \mathtt{DO}\ P\ \mathtt{END} \\
\mid\ & \mathtt{WHILE}\ X_i \neq 0\ \mathtt{DO}\ P\ \mathtt{END}
\end{aligned}
$$
The **LOOP programs** are the WHILE programs which contain no $\mathtt{WHILE}$ instruction.
:::

A **state** is a function $\sigma : \nat \to \nat$ with $\sigma(i) = 0$ for all but finitely many $i$; $\sigma(i)$ is the value of $X_i$. A program denotes a partial function on states.

:::definition{#def-loop-while-semantics}
The **semantics** $[\![P]\!]$ of a program $P$ is the partial function from states to states defined by induction on $P$:

- $[\![X_i \mathbin{:=} 0]\!](\sigma) = \sigma[i \mapsto 0]$, $[\![X_i \mathbin{:=} X_i + 1]\!](\sigma) = \sigma[i \mapsto \sigma(i) + 1]$, $[\![X_i \mathbin{:=} X_j]\!](\sigma) = \sigma[i \mapsto \sigma(j)]$;
- $[\![P ; Q]\!](\sigma) \simeq [\![Q]\!]([\![P]\!](\sigma))$;
- $[\![\mathtt{LOOP}\ X_i\ \mathtt{DO}\ P\ \mathtt{END}]\!](\sigma) \simeq [\![P]\!]^{n}(\sigma)$ where $n = \sigma(i)$ and $[\![P]\!]^n$ is the $n$-fold iterate of $[\![P]\!]$;
- $[\![\mathtt{WHILE}\ X_i \neq 0\ \mathtt{DO}\ P\ \mathtt{END}]\!](\sigma) \simeq [\![P]\!]^{n}(\sigma)$ for the least $n$ such that $[\![P]\!]^n(\sigma)\converge$ and $[\![P]\!]^n(\sigma)(i) = 0$, provided $[\![P]\!]^m(\sigma)\converge$ with $[\![P]\!]^m(\sigma)(i) \neq 0$ for every $m < n$; it is undefined if there is no such $n$.
:::

In a $\mathtt{LOOP}$ instruction, the number of iterations is the value of $X_i$ **on entry**: modifying $X_i$ inside the body does not change it. In a $\mathtt{WHILE}$ instruction, the condition is re-evaluated before each iteration.

:::definition{#def-loop-while-computes}
A program $P$ **computes** the partial function $f : \nat^k \rightharpoonup \nat$ defined by $f(\vec x) \simeq [\![P]\!](\sigma_{\vec x})(0)$, where $\sigma_{\vec x}(i) = x_i$ for $1 \leq i \leq k$ and $\sigma_{\vec x}(i) = 0$ otherwise. In words: the input is placed in $X_1, \dots, X_k$, all other variables are $0$, and the output is read in $X_0$. A function is **LOOP-computable** (resp. **WHILE-computable**) if it is computed by a LOOP (resp. WHILE) program.
:::

:::proposition{#prop-loop-total}
For every LOOP program $P$, $[\![P]\!]$ is total. Hence every LOOP-computable function is total.
:::

:::proof{of=prop-loop-total}
By induction on $P$: assignments are total, composition of total functions is total, and a finite iterate of a total function is total.
:::

## Programming in LOOP

We use abbreviations, each of which stands for a LOOP program using fresh auxiliary variables.

- **Addition** $X_0 \mathbin{:=} X_1 + X_2$: $\ X_0 \mathbin{:=} X_1 ;\ \mathtt{LOOP}\ X_2\ \mathtt{DO}\ X_0 \mathbin{:=} X_0 + 1\ \mathtt{END}$.
- **Predecessor** $X_0 \mathbin{:=} X_1 \dotminus 1$: $\ X_0 \mathbin{:=} 0 ;\ X_2 \mathbin{:=} 0 ;\ \mathtt{LOOP}\ X_1\ \mathtt{DO}\ X_0 \mathbin{:=} X_2 ;\ X_2 \mathbin{:=} X_2 + 1\ \mathtt{END}$. After $n \geq 1$ iterations, $X_2 = n$ and $X_0 = n - 1$.
- **Conditional** $\mathtt{IF}\ X_i \neq 0\ \mathtt{THEN}\ P\ \mathtt{END}$: compute $Y = \mathrm{sg}(X_i)$ in a fresh variable $Y$ (by a loop setting $Y$ to $1$ at each iteration), then $\mathtt{LOOP}\ Y\ \mathtt{DO}\ P\ \mathtt{END}$.

:::quiz[LOOP semantics]
What is the value of $X_0$ after running $X_0 \mathbin{:=} 0 ;\ \mathtt{LOOP}\ X_1\ \mathtt{DO}\ X_1 \mathbin{:=} X_1 + 1 ;\ X_0 \mathbin{:=} X_0 + 1\ \mathtt{END}$ with $X_1 = 3$?

- [x] $3$.

  The number of iterations is fixed on entry: the body runs three times, whatever happens to $X_1$ inside.
- [ ] The program does not terminate.

  It would with $\mathtt{WHILE}\ X_1 \neq 0$; LOOP programs always terminate.
- [ ] $6$.

  The number of iterations of $\mathtt{LOOP}\ X_1$ is fixed when the loop is entered, here $3$; modifying $X_1$ in the body does not change it.

---

In the predecessor program, why is the assignment $X_0 \mathbin{:=} X_2$ placed **before** $X_2 \mathbin{:=} X_2 + 1$ in the body?

- [x] So that $X_0$ always lags one step behind the counter $X_2$: after $n$ iterations $X_0 = n - 1$.
- [ ] The order does not matter.

  In the other order, $X_0$ would equal $n$ after $n$ iterations: the program would compute the identity.
- [ ] To make the program terminate on input $0$.

  LOOP programs always terminate; the order of the assignments determines the value computed, not termination.
:::

## LOOP programs compute the primitive recursive functions

:::theorem[Meyer–Ritchie]{#thm-loop-pr}
A function is LOOP-computable if and only if it is primitive recursive.
:::

We prove the two directions separately. In the first direction, programs for subfunctions are combined using **fresh** auxiliary variables, so that they do not interfere with each other.

:::proof{of=thm-loop-pr}
**Primitive recursive ⇒ LOOP.** We show by induction on a derivation of $f : \nat^k \to \nat$ that for all distinct indices $o, i_1, \dots, i_k$ there is a LOOP program, written $X_o \mathbin{:=} f(X_{i_1}, \dots, X_{i_k})$, which, started in any state $\sigma$, sets $X_o$ to $f(\sigma(i_1), \dots, \sigma(i_k))$ and modifies no variable other than $X_o$ and a finite set of auxiliary variables, which may be chosen disjoint from any given finite set of indices.

- Basic functions: $X_o \mathbin{:=} 0$, then $X_o \mathbin{:=} X_{i_1} ; X_o \mathbin{:=} X_o + 1$, and $X_o \mathbin{:=} X_{i_j}$.
- Composition $f = h \circ (g_1, \dots, g_m)$: choose fresh $Y_1, \dots, Y_m$, and run $Y_1 \mathbin{:=} g_1(\vec X) ; \dots ; Y_m \mathbin{:=} g_m(\vec X) ; X_o \mathbin{:=} h(Y_1, \dots, Y_m)$, with auxiliary variables of each subprogram chosen disjoint from $X_o$, $\vec X$, $\vec Y$.
- Primitive recursion, $f(\vec x, 0) = g(\vec x)$, $f(\vec x, y + 1) = h(\vec x, y, f(\vec x, y))$: with fresh $C$, $V$, $N$, run
$$
\begin{aligned}
& V \mathbin{:=} g(\vec X) ;\ C \mathbin{:=} 0 ;\ N \mathbin{:=} X_{i_{k+1}} ; \\
& \mathtt{LOOP}\ N\ \mathtt{DO} \\
& \qquad V \mathbin{:=} h(\vec X, C, V) ;\ C \mathbin{:=} C + 1 \\
& \mathtt{END} ;\ X_o \mathbin{:=} V.
\end{aligned}
$$
By induction on the number of iterations, after $j$ iterations $C = j$ and $V = f(\vec x, j)$. For $k = 0$, where $g$ is a constant $a$, the first assignment is $V \mathbin{:=} 0$ followed by $a$ instructions $V \mathbin{:=} V + 1$. The subprograms never rely on the initial values of their auxiliary variables, since each of these is assigned before being read; this is why they can be run repeatedly inside the loop. (Writing $V \mathbin{:=} h(\vec X, C, V)$ is allowed: the program for $h$ reads $V$ and writes into a fresh variable, which is then copied into $V$.)

The function $f$ itself is computed by $X_0 \mathbin{:=} f(X_1, \dots, X_k)$, whose auxiliary variables are chosen distinct from $X_0, \dots, X_k$.

**LOOP ⇒ primitive recursive.** Let $P$ be a LOOP program computing $f : \nat^k \to \nat$, and let $m$ be larger than $k$ and than the indices of all variables occurring in $P$. Variables of index $\geq m$ are not modified by $P$ and do not influence its effect on the others. We code the relevant part of a state by the sequence code $s = [\sigma(0), \dots, \sigma(m-1)]$ of the lesson :ref{to="models-of-computation/coding-sequences"}, and define $F_P(s)$ as the code of the state reached from $s$. We show by induction on subprograms $Q$ of $P$ that $F_Q$ is primitive recursive (on codes of length $m$):

- assignments: $F_{X_i := 0}(s) = \mathrm{set}(s, i, 0)$, $F_{X_i := X_i + 1}(s) = \mathrm{set}(s, i, (s)'_i + 1)$, $F_{X_i := X_j}(s) = \mathrm{set}(s, i, (s)'_j)$;
- sequence: $F_{Q ; R} = F_R \circ F_Q$;
- loop: $F_{\mathtt{LOOP}\ X_i\ \mathtt{DO}\ Q\ \mathtt{END}}(s) = G(s, (s)'_i)$ where $G(s, 0) = s$ and $G(s, n + 1) = F_Q(G(s, n))$, a primitive recursion.

Finally $f(\vec x) = \big(F_P([0, x_1, \dots, x_k, 0, \dots, 0])\big)'_0$, with $m$ entries in the code, is primitive recursive.
:::

:::quiz[the Meyer–Ritchie theorem]
In the direction "LOOP ⇒ primitive recursive", which construction corresponds to the instruction $\mathtt{LOOP}\ X_i\ \mathtt{DO}\ Q\ \mathtt{END}$?

- [x] A primitive recursion on the number of iterations, $G(s, n+1) = F_Q(G(s, n))$, evaluated at $n = (s)'_i$, the value of $X_i$ on entry.
- [ ] A bounded minimization.

  Bounded minimization is a derived scheme; the natural translation of a loop is iteration, i.e. primitive recursion.
- [ ] A course-of-values recursion.

  Each iteration only needs the state after the previous iteration.

---

Why does the proof work with codes of the whole state rather than with the values of individual variables?

- [x] A loop body updates several variables at once; iterating it is a primitive recursion only if the full state is a single argument of the iterated function.

  This is where the coding of finite sequences is used.
- [ ] Because primitive recursive functions cannot take several arguments.

  Primitive recursive functions take any fixed number of arguments; the issue is that a primitive recursion iterates a single value.
- [ ] To make the semantics deterministic.

  The semantics is deterministic in any case; coding the state is what turns the iteration into a primitive recursion.
:::

## Exercises

::::exercise{difficulty=1}
Write LOOP programs computing $x \cdot y$, $x^y$, and $\mathrm{sg}(x)$.

:::solution
$x \cdot y$: $X_0 \mathbin{:=} 0 ;\ \mathtt{LOOP}\ X_2\ \mathtt{DO}\ \mathtt{LOOP}\ X_1\ \mathtt{DO}\ X_0 \mathbin{:=} X_0 + 1\ \mathtt{END}\ \mathtt{END}$.

$x^y$: $X_0 \mathbin{:=} 0 ; X_0 \mathbin{:=} X_0 + 1 ;\ \mathtt{LOOP}\ X_2\ \mathtt{DO}\ Y \mathbin{:=} 0 ;\ \mathtt{LOOP}\ X_1\ \mathtt{DO}\ \mathtt{LOOP}\ X_0\ \mathtt{DO}\ Y \mathbin{:=} Y + 1\ \mathtt{END}\ \mathtt{END} ;\ X_0 \mathbin{:=} Y\ \mathtt{END}$ (each round multiplies $X_0$ by $x$).

$\mathrm{sg}(x)$: $X_0 \mathbin{:=} 0 ;\ \mathtt{LOOP}\ X_1\ \mathtt{DO}\ X_0 \mathbin{:=} 0 ;\ X_0 \mathbin{:=} X_0 + 1\ \mathtt{END}$.
:::
::::

::::exercise{difficulty=2}
Show that the functions computed by LOOP programs of **nesting depth** at most $1$ (no $\mathtt{LOOP}$ inside a $\mathtt{LOOP}$) are bounded by linear functions: for each such program computing $f$ there are $a, b$ with $f(\vec x) \leq a \cdot |\vec x| + b$. Deduce that multiplication requires nesting depth at least $2$.

:::solution
Consider a state $\sigma$ and let $M = \max_i \sigma(i)$. Each assignment increases the maximum of the values by at most $1$. A loop-free program with $c$ instructions therefore maps a state of maximum $M$ to one of maximum at most $M + c$. A loop $\mathtt{LOOP}\ X_i\ \mathtt{DO}\ Q\ \mathtt{END}$ with loop-free $Q$, entered in a state of maximum $M'$, runs at most $M'$ times, so the maximum becomes at most $M' + cM'$. A sequence of $\ell$ such instructions multiplies the maximum by at most a constant and adds a constant. Hence $f(\vec x) \leq a |\vec x| + b$. Multiplication is not linearly bounded ($x \cdot x$), so it needs nested loops. (Meyer and Ritchie studied the classes $\mathcal{L}_n$ of functions computed by LOOP programs of nesting depth at most $n$. For $n \geq 2$, $\mathcal{L}_n$ is the level $\mathcal{E}^{n+1}$ of the **Grzegorczyk hierarchy**, which stratifies the primitive recursive functions by growth rate.)
:::
::::

## Notes and references

LOOP programs and the characterization of the primitive recursive functions are due to Meyer and Ritchie, who also related the nesting depth of loops to the Grzegorczyk hierarchy. That structured programs without `while` loops compute exactly the primitive recursive functions is also part of the theorem that Monin and Patey credit to Wang (1957), Péter (1958) and Ershov (1958); their chapter "Church–Turing thesis" proves it with programs on registers.

- A. R. Meyer, D. M. Ritchie, *The complexity of loop programs*, Proceedings of the 22nd ACM National Conference (1967), 465–469.
- A. Grzegorczyk, *Some classes of recursive functions*, Rozprawy Matematyczne 4 (1953).
- H. Wang, *A variant to Turing's theory of computing machines*, Journal of the ACM 4 (1957), 63–92.
- R. Péter, *Graphschemata und rekursive Funktionen*, Dialectica 12 (1958), 373–393.
- B. Monin, L. Patey, *Computability theory*, chapter "Church–Turing thesis", section on recursive functions.
